# 🚀 LiveCode — Complete Production Deployment Guide

This guide walks you through deploying **LiveCode** to production using:
- **Database**: [Neon](https://neon.tech) (Serverless PostgreSQL — Free & Recommended) or [Render Postgres](https://render.com)
- **Backend API & WebSockets**: [Render](https://render.com) (Node.js Web Service)
- **Frontend SPA**: [Vercel](https://vercel.com) (React + Vite)

---

## Part 1: Database Setup (PostgreSQL)

You have two simple options. **Option A (Neon)** is recommended because your server code is already wired with `@prisma/adapter-neon` for serverless connection pooling.

### Option A: Neon.tech (Recommended, Free, 2-Minute Setup)

1. Go to [https://neon.tech](https://neon.tech) and sign up with GitHub or Google.
2. Click **Create Project**:
   - Name: `livecode-db`
   - Region: Select the region closest to your users (e.g. `US East (N. Virginia)` or `EU (Frankfurt)`).
   - Postgres version: Default (16 or 17).
3. Click **Create Project**.
4. You will immediately see a **Connection Details** dashboard:
   - Make sure **Connection pooling** is checked.
   - Select **Prisma** from the connection string dropdown.
   - Your connection string will look like:
     ```text
     postgresql://neondb_owner:YOUR_PASSWORD@ep-XYZ-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require
     ```
5. Save this URL — this is your `DATABASE_URL`.

#### How Database Migrations and Seeding Work:
- When the server starts up, it automatically runs:
  1. `npm run db:deploy` (executes `prisma migrate deploy` which applies all 7 Prisma SQL migrations to your database schema).
  2. `seedProblems()` (automatically inserts starter algorithm problems: *Two Sum*, *Valid Parentheses*, *Reverse Linked List*).
- **You do NOT need to run any manual SQL commands.**

---

### Option B: Render Managed PostgreSQL (Alternative)

If you prefer everything in one dashboard:
1. On [Render](https://dashboard.render.com), click **New +** -> **PostgreSQL**.
2. Name: `livecode-postgres`.
3. Database: `neondb`.
4. User: `livecode_user`.
5. Plan: **Free** (or Starter for non-expiring database).
6. Click **Create Database**.
7. In the database dashboard, copy the **Internal Database URL** (if backend is on Render) or **External Database URL**.

## Part 2: Backend Deployment on Render

### Step 1: Push Code to GitHub
Ensure your latest changes are pushed to your GitHub repository.

### Step 2: Deploy Using Render Blueprint (Fastest)
The repository includes a [render.yaml](file:///d:/CV%20projects/livecode/render.yaml) file configured specifically for this stack:
1. In Render Dashboard, click **New +** -> **Blueprint**.
2. Connect your GitHub repository.
3. Render will detect `render.yaml` and set up the `livecode-backend` web service.
4. Render will prompt you for the missing environment variables:
   - `DATABASE_URL`: Paste your Neon connection string from Part 1.
   - `CLIENT_URL`: `https://your-app.vercel.app` (you can update this after creating Vercel app).
   - `SERVER_URL`: `https://livecode-backend.onrender.com` (your Render service URL).
   - `GOOGLE_CLIENT_ID`: Your Google OAuth Client ID.
   - `GOOGLE_CLIENT_SECRET`: Your Google OAuth Client Secret.
   - `GROQ_API_KEY`: Your key from [console.groq.com](https://console.groq.com).
   - `JUDGE0_URL`: `https://ce.judge0.com`
   - *Note: `JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` are automatically generated by Render with secure 256-bit random keys.*

### Step 3: Manual Setup (If not using Blueprint)
If creating the Web Service manually:
- **Service Type**: Web Service
- **Root Directory**: `server`
- **Environment**: Node
- **Build Command**: `npm install && npx prisma generate && npm run build`
- **Start Command**: `npm run db:deploy && npm start`
- **Health Check Path**: `/api/v1/health`
- **Environment Variables**: Add all variables from [server/.env.example](file:///d:/CV%20projects/livecode/server/.env.example).

## Part 3: Frontend Deployment on Vercel

1. Go to [https://vercel.com](https://vercel.com) and sign in.
2. Click **Add New...** -> **Project**.
3. Import your GitHub repository.
4. In the configuration screen:
   - **Framework Preset**: Vite
   - **Root Directory**: Click `Edit` and select **`client`**.
   - **Build Command**: `npm run build` (or `tsc -b && vite build`)
   - **Output Directory**: `dist`
5. Expand **Environment Variables** and add:
   - `VITE_API_URL`: `https://your-backend.onrender.com` (NO trailing slash)
   - `VITE_SOCKET_URL`: `https://your-backend.onrender.com` (NO trailing slash)
6. Click **Deploy**.
7. Once deployed, Vercel gives you your live URL (e.g. `https://livecode-client.vercel.app`).

---

## Part 4: Google Cloud OAuth Configuration

To enable Google sign-in in production:
1. Open [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
2. Select your project and click on your **OAuth 2.0 Client ID**.
3. Under **Authorized JavaScript origins**, add:
   - `https://your-app.vercel.app`
   - `https://your-backend.onrender.com`
4. Under **Authorized redirect URIs**, add:
   - `https://your-backend.onrender.com/api/auth/google/callback`
5. Click **Save**.

---

## Part 5: Final Cross-Connection Check

1. In Render Dashboard (`livecode-backend` -> Environment):
   - Verify `CLIENT_URL` is set to `https://your-app.vercel.app`.
   - Verify `SERVER_URL` is set to `https://your-backend.onrender.com`.
2. In Vercel Dashboard (`Settings` -> Environment Variables):
   - Verify `VITE_API_URL` is set to `https://your-backend.onrender.com`.
   - Verify `VITE_SOCKET_URL` is set to `https://your-backend.onrender.com`.
   - If you changed these, trigger a Redeploy in Vercel.
